# 教程重新编写规范

基础教程与项目实践使用相同的[LangChain风格文档框架](./frontend-page-design.md)。旧教材与旧项目源码已经退出新仓库，后续从明确任务重新编写。

当前FastAPI基础课的章节/前置/demo路线以[课程设计](./fastapi-curriculum.md)为准：一章一个页面，章节内连续阅读，不将全部教程混进一页。企业工程习惯逐步引入，首例与结课demo属于基础课，不直接改写为独立企业业务项目课程。

## 先设计一个小任务

每批最多2–3个学习主题或一个项目阶段。记录学习者已知什么、缺什么、当前完成目标、成功/失败观察与恢复点。首次使用的Python/工具/业务概念必须在当前需要之前解释，不能把必需补课藏进未来章节。

基础课先让最小操作运行；项目课先呈现简单可用版本和具体局限，再逐步改造。两类页面共享连续章节、代码组、图和目录，不使用不同主题或一屏仪表盘替代解释。

## 专业词汇与通俗理解

后续所有课程都保留专业名称和准确语义，同时为第一次出现的概念提供白话解释。不能只给英文术语、定义或链接，就要求学习者继续操作。

一个新概念按下面的顺序说明：

1. 写出专业名称和最小准确定义。
2. 用一句日常语言说明它当前做什么、解决什么问题。
3. 对理解门槛较高的概念，至少给一个常见生活例子或比喻，明确例子中的角色与技术角色如何对应。
4. 回到本步代码或命令，指出输入、处理、结果与可观察现象；必要时说明类比哪里不成立。
5. 让学习者修改一个条件、预测结果或用自己的话回讲，再核对解释。

类比是理解的桥梁，不是技术定义的替代品。不为每句解释强加比喻，也不一次引入多套互相冲突的类比。必需解释直接放在正文，补充故事可以展开，不能让学习者先完成操作才看到前提。

| 概念 | 可用的生活例子 | 回到技术机制与边界 |
| --- | --- | --- |
| 当前工作目录（CWD）与相对路径 | 像站在一个房间里找“旁边的抽屉”；先知道自己在哪个房间，才知道“旁边”指哪里 | 相对路径从当前目录计算；切目录不会自动切换解释器 |
| 虚拟环境 | 每个项目各用一套工具箱，需要的工具放在各自箱中 | 对应独立的解释器入口和包安装位置；不是另一台电脑，也不是所有系统资源都隔离的容器 |
| 函数定义与调用 | 写下菜谱只是定义步骤，拿食材按菜谱做一次才是调用 | 参数是本次输入，函数体执行处理，返回值交给调用处；定义时不执行函数体 |
| 类型提示（annotation） | 给物品贴“应放整数”的标签，帮助人检查，但标签本身不会拦住放错物品 | 普通Python直接调用不会按注解自动验证；框架或检查工具如何使用注解，要另行解释 |

解释赋值时使用“名称引用一个值”的准确说法，不把变量一概比作装着值的独立盒子，避免误导后续的共享引用、可变对象与重新赋值。

## Windows 主线与命令编写

所有有终端操作的章节必须给出可跟做的 Windows 命令。默认展示“Windows · PowerShell”，同时提供“macOS · Linux”明确切换项；系统与shell名称放在代码框外，代码框内只保留真实命令和必要原因注释。Python源码跨平台相同的部分只讲一份，不复制整章。

每个操作步骤交代：

- 操作系统与shell，以及当前工作目录；不只写“在终端运行”。
- Python版本、解释器入口、已安装的包及当前需要的导入；标准库也说明无需额外安装。
- 命令的动作、关键参数、相对或绝对路径、引号和环境变量的含义。带空格路径需要给出目标shell正确的写法。
- 先保存哪个文件，再运行哪条命令；需要多个终端时说明各自职责，服务需要停止或重启时给出对应操作。
- 明确的成功观察、失败信息与恢复步骤；执行验证记录与教学示意分别标明。

Windows以PowerShell为主线，不默认要求WSL或Git Bash。cmd、PowerShell与Bash的语法可能不同，不把它们混写；如果仅提供PowerShell版本，应明确要求在PowerShell执行。不要为了覆盖所有shell添加未经运行验证的同义命令。

不同系统的命令分别从已发布的真实源码提取，固定各自SHA/hash/行号，并记录实际验证的平台。切换平台不能更换Python示例逻辑或引入未来章节尚未讲的工具；相同命令可合并说明，但Windows入口仍要清楚可见。

## 一个小节的理解循环

1. 说明当前现象、目标和已知条件。
2. 用专业名称和白话解释机制与语法，复杂概念配生活例子，再回到当前代码；类比不能替代技术定义。
3. 给一个可预测的问题，再修改一个条件。
4. 交代文件完整路径、父目录、插入/替换位置，写一小块完整语义代码。
5. 代码有原因注释，块后解释输入、判断和结果。
6. 用明确命令/请求观察成功和失败，再给恢复与回讲。

首例不提前引入身份、数据库和企业资源。代码块按机制而不是固定行数分割；完整路由/函数不可裁成无法独立理解的碎片。

首次名称/语法必须具体解释，例如`app = FastAPI()`分别说明来源、大写拼写、调用创建对象、赋值引用、应用与监听区别；装饰器、类型提示、class/BaseModel、Depends、yield/Session、await等同样记录首次解释位置。正式写作按requiresConcepts/introducesConcepts追踪，缺前置就就地补课或后移，不只给术语链接。

## 真实源码与检查点

新源码随新教程建立，不能手抄第二套页面代码。每个检查点提供完整文件集合、依赖版本、工作目录、解释器、入口与可运行状态。局部片段从对应完整版本提取，源码hash与当前代码组一致。

临时不可运行编辑状态明确注明；只能对真正可运行的完整集合记录成功。恢复来源有独立完整文件，不把未来文件混入前面检查点。配置/数据库/权限/并发改造分别补必要前置与代价。

学习页提供可点击的本章完整源/当前文件/关键行/恢复版本；每个sourceRef固定各自已推送的40位提交SHA及文件hash。源码先发布、页面后引用；路径/行号/远端对象没有实际核验前不显示链接，不用main最新代码解释旧步骤。demo与独立lab各自登记sourceRoot，构建取源失败不能回填工作树或伪造样例。

每章图先有因果问题/边界/条件/当前源对应，再做对齐、间距、双主题和手机构图；默认3–7节点，不为凑数量增删条件。复杂图拆图或记录8–9节点的必要性与视觉验收；流程示意、作者真实行为和学习者观察分开，不以现有简单组件图替代正式教材设计。

## 运行与学习验收分别记录

作者在新环境运行、代码测试、页面组件检查、初学者跟做和部署检查是不同证据。记录版本、输入、稳定输出、错误原文与恢复复测；图和预设响应标演示，不冒充真实执行。

正文能否通俗、预测能否解释和失败能否恢复，需要人工回讲/跟做，不由字符数、点击完成或测试数量代替。缺真实学习者反馈时注明待验证，不能提前声称教学完成。

每批审阅还需检查：Windows主线是否默认可见、每条命令的shell/CWD/前置是否明确、首次专业词汇是否有白话解释、较难概念是否有准确生活例子、类比是否回到真实代码并交代边界。缺项应在扩写下一批之前修正。
